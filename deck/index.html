Verifiable rewards
for biology.

A deterministic verifier layer for probabilistic biology agents. The generator dreams. The reward function checks.

R(x) = 1[gates pass] · Σ wi · φi( gi(x) )
The problem

Hallucination is a feature, until it isn't.

An LLM inventing a hypothesis is being creative. An LLM inventing a melting temperature, a PAM site, or a citation is just wrong, with total confidence.

Agentic biology workflows mix both jobs in one model. The probabilistic engine that makes discovery possible is the same engine that quietly fabricates the numbers a wet lab will spend real money and months on.

// creativity and precision are different jobs. they should not share a failure mode.
Why this works

Math and code got trustworthy because correctness got cheap to check.

Reasoning models leapt forward on a simple loop: a proof verifier, a unit test, a compiler says right or wrong, and the model learns from it. The name is RLVR, reinforcement learning with verifiable rewards.

Biology has almost none of these verifiers. So bio-agents drift, and no one can tell a grounded answer from a fluent one at scale.

Build the missing verifiers, and biology gets the same flywheel.

The contract

One reward skeleton. Any domain.

R(x) = 1[ hard gates pass ] · Σi wi · φi( gi(x) )
  • xThe candidate the agent proposes. It only ever passes x. It never touches the scoring code. That sealed boundary is the safety story.
  • giA deterministic measurement. A melting temperature, a docking energy, a metabolic flux, a conservation score.
  • φiA calibrated membership function. Trapezoids that encode biological sweet spots: too little is bad and too much is bad.
  • 1[ ]Hard gates. Anything physically impossible scores exactly zero. No partial credit for chemistry that cannot exist.
What makes a reward trustworthy

Five properties, non-negotiable.

01 / determinism

Decimal arithmetic, fixed rounding, hashed config. Same input, same bytes, on every machine. Results cache and reproduce.

02 / calibration

Membership anchors come from a reference panel of known positives and negatives, set before any novel candidate is scored.

03 / hard gates

Validity is not a soft penalty. Impossible is zero, kept separate from the graded quality score.

04 / applicability

Every result says whether the candidate is inside the verifier's competence. A reward that extrapolates silently is worse than none.

05 / goodhart-resistant

Multiple objectives, hard gates, and adversarial negative controls make the metric expensive to game.

the origin lesson

A docking reward once scored a drug-resistant enzyme identically to wild type. It was blind and did not say so. Property 04 exists because of that.

The one to say out loud

An agent cites a structure. The layer refuses it.

agent: "PDB 5EHF is the VEGFR2 complex, bound at 3.37 nM."
REJECTED   reward = 0.000
// entity provenance contradicted: PDB 5EHF is 'laccase', claimed 'VEGFR2'

The number was plausible. The wording was fluent. The provenance was fiction, and 5EHF is a completely different enzyme. A deterministic entity check caught it where a reader would have nodded along. This is anti-hallucination discipline turned into a gradient any agent can be trained against.

How it stays honest and portable

Sealed boundary. Mock-backed providers.

the sealed boundary

The agent proposes. It cannot score.

The candidate crosses one wall as data. The reward logic and its hashed config live on the other side. A probabilistic generator can never quietly edit its own grader.

the provider pattern

Every expensive step has a mock.

Docking, folding, an FBA solve, a DOI lookup, each is an injected provider with an offline stand-in. The reward logic stays pure and testable, and every demo runs with no GPU and no network.

Real providers plug straight in: ESMFold or Boltz for binder confidence, the cobrapy textbook model for metabolic flux, live Crossref and RCSB for citations.
